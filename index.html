Context / Goal

금융사 현업 직원이 소스코드와 SQL 로직을 이해하기 위해 개발자에게 반복적으로 문의하는 상황이 있었습니다. 이를 줄이기 위해 자연어 질문으로 업무 로직을 찾고, 관련 코드·SQL·실행 결과를 함께 확인할 수 있는 LLM 기반 업무 지원 Agent를 개발했습니다. 사내 생산성 향상, 정보 검색 고도화, 사용자 지원, 운영 효율화를 목표로 약 6개월간 PoC를 진행했고, 종료 직전 설문에서 긍정적인 평가를 받았습니다.

Constraints

  • 폐쇄망 / Local LLM: 금융권 내부 환경에서 Local LLM을 안정적으로 서빙하고 Agent 기능을 구동해야 했습니다. 외부 SaaS/API에 기대기 어려워 모델 호출, 검색, 도구 실행 흐름을 내부 환경에 맞게 구성해야 했습니다.
  • 신뢰성 요구: 사용자가 답변의 근거와 검색 결과의 관련성을 확인할 수 있어야 했습니다.
  • 코드베이스 / 사내 메타데이터: 방대한 코드 스페이스와 사내 메타데이터를 기반으로 복잡한 파일명, 변수명, 함수명, 업무 명명 규칙을 이해하는 Agent가 필요했습니다.
  • Workflow 설계: 코드 검색, SQL 분석, 실행, 다이어그램 생성 등 여러 작업을 단일 답변 흐름으로 연결해야 했습니다.
  • 실행 기능 제어: SQL 실행, Python 실행 등 위험도가 있는 기능은 격리된 환경에서 다뤄야 했습니다.

Problem Definition

코드 QA에서는 명확한 정답이 없는 질문이 많았습니다. 따라서 단순 accuracy가 아니라 사용자 질의, 검색된 코드, 모델 답변 사이의 관련성을 어떻게 수치화하고 사용자가 검토할 수 있게 할 것인가를 핵심 문제로 정의했습니다.

Solution

  • Tree-sitter 기반 AST parsing으로 코드 구조를 분석하고, code embedding search와 grep/glob 기반 lexical search를 함께 사용했습니다.
  • 사내 명명 규칙을 용어 사전 형태로 정리하고, Agent가 질의 처리 중 해당 사전을 검색해 파일명·변수명·함수명의 의미를 보완하도록 구현했습니다.
  • 코드 분석, SQL 분석·작성·실행, Python sandbox, 다이어그램 생성 기능을 Agent 도구로 구성했습니다.
  • 단일 질의응답이 아니라 검색·분석·실행·근거 제시가 이어지는 Agentic Workflow로 구성하고, context 구성 방식과 tool 사용 흐름을 반복 개선했습니다.
  • 관련성 점수는 context compaction 연구의 log-likelihood/perplexity 활용 방식에서 아이디어를 얻어 설계했습니다.

Evaluation / Improvement

  • RepoQA[1], SWE-QA[2] 등 repository-level QA benchmark를 사용해 코드 분석 성능과 관련성 점수 기능을 점검했습니다.
  • 검색 전략, context 구성, 답변 근거 표시 방식의 변경 전후를 비교하며 품질과 속도 저하 여부를 함께 확인했습니다.
  • PoC 사용자 피드백을 바탕으로 답변 근거 표시와 관련성 점수의 표현 방식을 개선했습니다.
[1] RepoQA: Jiawei Liu et al., "RepoQA: Evaluating Long Context Code Understanding," arXiv:2406.06025, 2024.
[2] SWE-QA: Weihan Peng et al., "SWE-QA: Can Language Models Answer Repository-level Code Questions?" arXiv:2509.14635, 2025.
