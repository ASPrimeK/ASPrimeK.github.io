Context / Goal

금융권 폐쇄망 환경에서 개발 지식이 깊지 않은 현업 담당자가 소스코드·SQL·문서를 질문하고 업무 로직을 확인할 수 있는 LLM 기반 업무지원 Agent를 구현했습니다. 자연어 질문으로 관련 코드·SQL·실행 결과와 답변 근거를 함께 확인할 수 있도록 구성했고, 보안·정확성·현업 수용성을 고려해 약 50명 규모 부서가 6개월간 PoC로 사용했습니다.

Constraints

  • 폐쇄망 / Local LLM: 금융권 내부 환경에서 Local LLM을 안정적으로 서빙하고 Agent 기능을 구동해야 했습니다. 외부 SaaS/API에 기대기 어려워 모델 호출, 검색, 도구 실행 흐름을 내부 환경에 맞게 구성해야 했습니다.
  • 신뢰성 요구: 사용자가 답변의 근거와 검색 결과의 관련성을 확인할 수 있어야 했습니다.
  • 코드베이스 / 사내 메타데이터: 여러 코드 저장소와 사내 메타데이터를 기반으로 파일명, 변수명, 함수명, 업무 명명 규칙을 함께 검색할 수 있어야 했습니다.
  • 처리 흐름 설계: 코드 검색, SQL 분석, 실행, 다이어그램 생성 등 여러 작업을 하나의 답변 흐름으로 연결해야 했습니다.
  • 실행 기능 제어: SQL 실행, Python 실행 등 위험도가 있는 기능은 격리된 환경에서 다뤄야 했습니다.

Problem Definition

코드 QA에서는 명확한 정답이 없는 질문이 많았습니다. 따라서 단순 accuracy가 아니라 사용자 질문, 검색된 코드, 모델 답변이 서로 맞는지 확인하고 사용자가 근거를 검토할 수 있게 할 것인가를 핵심 문제로 정의했습니다.

Solution

  • Tree-sitter로 코드 구조를 분석하고, 의미 기반 검색과 키워드 검색을 함께 사용했습니다.
  • 코드 검색, SQL 실행, Python 샌드박스 기능을 Agent 백엔드에서 호출할 수 있도록 도구 인터페이스를 구성했습니다.
  • 사내 명명 규칙을 용어 사전 형태로 정리하고, Agent가 질의 처리 중 해당 사전을 검색해 파일명·변수명·함수명의 의미를 보완하도록 구현했습니다.
  • 코드 분석, SQL 분석·작성·실행, Python 실행, 다이어그램 생성 기능을 Agent 도구로 구성했습니다.
  • 단일 질의응답이 아니라 검색·분석·실행·근거 제시가 이어지도록 구성하고, 답변에 들어갈 코드·문서 범위와 도구 사용 흐름을 반복 개선했습니다.
  • 검색된 코드와 사용자 질문이 얼마나 관련 있는지 표시하는 점수를 설계해, 사용자가 답변 근거를 검토할 수 있도록 했습니다.

Evaluation / Improvement

  • 실제 코드 저장소를 대상으로 한 질문·답변 사례를 참고해 코드 검색 결과와 답변 근거가 질문에 맞는지 점검했습니다.
  • 검색 전략, 답변에 포함할 코드·문서 범위, 답변 근거 표시 방식의 변경 전후를 비교하며 품질과 속도 저하 여부를 함께 확인했습니다.
  • PoC 사용자 피드백을 바탕으로 답변 근거 표시와 관련성 점수의 표현 방식을 개선했습니다.
